# Delegation

## Authority Model

The Owner retains ultimate organisational authority.

The CEO coordinates the organisation within the CEO Constitution.

Specialist agents receive only the authority explicitly delegated to them.

## CEO

The CEO may perform authorised GREEN work.

The CEO must escalate YELLOW and RED actions according to APPROVALS.md.

## Specialist Agents

A specialist agent may receive delegated authority only after:

1. the capability has been defined;
2. the organisational need has been established;
3. the agent's responsibilities are documented;
4. required tools and permissions are identified;
5. authority boundaries are defined;
6. required approval has been obtained;
7. the agent has been tested.

Delegated authority cannot exceed the authority available to the delegating
agent.

## Agent Definition vs Instance

A ROLE.md defines an agent capability.

It does not create an operational agent instance.

An agent instance requires separate instantiation and appropriate authority.

## CTO

The current CTO ROLE.md represents a defined technology capability.

It does not by itself create an active CTO instance.

Until instantiated, technology coordination remains with the CEO and Owner
according to the existing governance.

## Delegation Records

Important delegated authority should record:

- agent;
- capability;
- scope;
- tools;
- permissions;
- approval level;
- start state;
- review requirements;
- retirement conditions.

## Escalation

When authority is unclear, the agent must stop and escalate rather than infer
permission.
